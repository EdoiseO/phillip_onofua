The product challenge

Keep the whole exchange connected.

A useful marketplace needs more than a feed. Students need to understand an item, contact its seller, manage a listing, and get help when something needs attention.

Under the interface

Three decisions that shaped the system.

The work connects product behaviour to the data rules that make it consistent when requests fail, people retry, or permissions change.

01

Make selling recoverable.

Listing creation coordinates form data, images and publication state. A stable operation identifier lets an interrupted request retry the original write without creating a second listing.

The tradeoff: More explicit workflow state, in exchange for clearer recovery after a network failure.

How the write works

Creation, editing and retirement use durable write intents. Image paths are reserved before upload; the commit verifies ownership, revision and image order. Status changes use a separate retry-safe operation. Abandoned uploads enter a bounded cleanup queue.

02

Keep realtime grounded in stored history.

Messages and reactions arrive live, while paginated database history remains the source of truth. A thread starts with 40 messages and keeps a bounded client window.

The tradeoff: Older messages load on demand instead of keeping an entire conversation in browser memory.

How messaging stays consistent

Stable message IDs reconcile inserts with existing history. Media sends reserve exact owner and conversation paths before upload. Notification updates use an invalidation signal, then refetch the recipient’s authorized notification data.

03

Make authority explicit.

Review tools connect a decision to its subject, rationale and history. Server checks and database policies enforce the relevant permissions around the workflow.

The tradeoff: More deliberate access checks and recorded transitions, with a clearer account of who can do what.

How the boundaries are organized

Public profiles, participant conversations, moderation context and service operations use separate access paths. Registration checks supported Toronto school email domains. The September implementation adds current-authority checks for private reads and browser-bound password recovery; hosted validation is still in progress.
