Inside the project · Windows desktop application

Overlay Studio

A Windows desktop app for building and running live OBS overlays. It brings a library of 12 overlay types, live previews, audio-reactive animation, and saved settings into one place.

Watch · Live output

Keep the preview and browser source in sync

The desktop app, its preview, and OBS run in separate contexts. I connected them through a local Python server and WebSockets, so settings and Windows media updates appear in the browser source without rebuilding the OBS scene.

That connection brings native media data, saved settings, and live browser output together in one workflow.

01 · Overlay library

Twelve overlays, one library

Choose an overlay, customize it, and copy its browser-source URL into OBS. Multiple instances of the same type can keep separate settings.

The catalog is assembled from local overlay manifests, and each instance has its own saved configuration.

02 · Audio-reactive animation

Make the dance follow the sound

The Dancing GIF overlay reacts to the audio playing on the computer, so a beat can bring the animation to life.

A local Windows audio loopback worker analyzes the sound spectrum and bass levels, then sends beat and level updates to the overlay. It listens to the whole output device, including game and voice audio.

03 · Being a good API citizen

Share requests and slow down when needed

Several overlays can follow the same Rivals player without each making its own requests. When the service has trouble, the last successful state stays visible.

The worker shares fetches per player, enforces an app-wide budget of 120 requests per hour, backs off after errors and rate limits, and adds startup delays and jitter to avoid bursts.

04 · Local server security

Keep outside websites from changing settings

A random website should not be able to change an active overlay in the background.

Mutating API requests require JSON. Browser requests with an Origin or Referer must also match the local server's origin; local tools without those browser headers remain supported. Tests cover allowed and rejected requests.

05 · Privacy

Keep the linked player ID private

The overlay can show a player's rank and session record without exposing the linked player ID to its browser clients.

The ID is kept in server-side bookkeeping and used for requests to Rivals Data. It is excluded from the app's API responses and WebSocket messages.

06 · Shipping the app

Make the library practical to use

A PyInstaller one-file Windows executable gives the desktop app a packaged entry point. The library supports custom media and drag-to-reorder, with saved order between launches.

Supported social overlays can also export the current draft as a transparent PNG for video editors, end cards, and lower thirds.

Under the hood · Live preview

Preview changes without interrupting the stream

Editing an overlay should show a live preview without sending unfinished settings to an active OBS scene. The customizer keeps an unsaved draft in its preview while the browser source continues using the saved settings.

When the user saves, the local server stores the settings for that overlay instance and broadcasts its updated configuration to connected browser sources.
